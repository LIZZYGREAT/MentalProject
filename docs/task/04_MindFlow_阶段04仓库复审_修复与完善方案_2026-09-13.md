# 四、P0：中文 Memory Retrieval 当前会注入无关记忆

## 现状

当前 `ParticipantMemoryRepository.retrieve()` 主要通过：

```python
str(query).split()
```

生成关键词。

对中文：

```text
“我下个月论文答辩要准备什么？”
```

通常没有空格，难以和：

```text
“我下个月要参加毕业论文答辩”
```

形成有效 token overlap。

更严重的是：

```text
当所有 memory relevance score = 0
```

当前逻辑仍然会选若干条 Memory 注入 Prompt。

于是可能出现：

```text
用户问天气
→ 注入论文目标、作息、旧背景
→ Agent 被无关个性化干扰
```

被选中的无关 Memory 还会记录 `last_used_at`，进一步污染 retrieval usage。

## 修改

v1 不需要向量数据库。

改成轻量中文友好 relevance：

```text
1. normalized exact substring
2. CJK bigram / trigram overlap
3. ASCII token overlap
4. memory_type boost
5. recency / last_used 只做 tie-breaker
```

例如：

```text
论文答辩
→ 论文 / 文答 / 答辩
```

增加硬门槛：

```text
query 非空且 relevance == 0
→ 默认不返回该 memory
```

不要为了凑满 5 条而注入无关内容。

### 字符预算

当前第一条 Memory 可能突破 `max_chars`。

应严格：

```python
if total + size > max_chars:
    continue
```

不论 selected 是否为空。

### 测试

```text
Memory: “下个月要论文答辩”
Query: “论文答辩要准备什么”
→ 命中

Query: “今天天气怎么样”
→ 不返回论文 memory

全部无关
→ []

返回内容总字符
→ <= 1200
```

# 六、P0：Psychological Context 目前几乎每个 Agent Turn 都会加载

当前 Worker 会并行：

```text
memory.retrieve(...)
preferences.get(...)
psychological_context_builder.build(
    current_text=turn_input.text
)
```

但 `PsychologicalContextBuilder.current_text` 当前没有真正参与 feature relevance selection。

所以：

```text
“帮我查明天几点上课”
“Transformer 是谁提出的？”
“谢谢”
```

也可能带着：

```text
recent_stress
recovery_trend
academic_load
```

进入 Prompt。

这会造成明显的“系统一直在用心理画像理解我”的用户感知。

## 修改：Psychological Relevance Gate

Psychological Context 默认只在以下类型注入：

```text
情绪/状态表达
压力
疲劳
睡眠/恢复
任务负荷
关怀请求
压力曲线相关解释
自我状态总结
“为什么提醒我”
```

以下默认不注入：

```text
Calendar CRUD
课程表编辑
功能介绍
绑定/OAuth
普通事实问答
Web Search
普通“谢谢”
无关技术问题
```

v1 可先做 Backend deterministic：

```text
psych_context_relevant(text, route/tool intent) -> bool
```

False 时：

```text
psychological_context = None
```

不要只靠 Agent 自己忽略无关 Context。

# 七、P1：Psychological Context 的 confidence / provenance / expiry 需要收紧

当前 Builder 已经输出：

```text
time_window
valid_until
confidence
source
evidence_type
model_version
```

方向正确，但细节还需要改。

## 1. confidence

不要把：

```text
LearnedModelProfile.confidence
```

借给：

```text
rolling_7d_stress
rolling workload
recovery trend
```

因为两者不是同一个统计含义。

规则：

```text
source 自带 confidence
→ 使用

source 没有 confidence
→ null
或 evidence_strength enum
```

不要制造伪精确数值。

## 2. valid_until

不要每次 build 都：

```text
valid_until = build_now + TTL
```

否则旧证据会不断续命。

应：

```text
valid_until = source_at + feature_ttl
```

例如：

```text
current observation + 24h
event frustration   + 72h
slow state          + 7d
```

## 3. provenance

每个 feature 增加：

```text
source_at
```

而不是只有 `source` 名称。

## 4. 命名

如果 `rolling_7d_workload` 不严格等于学业负荷，建议：

```text
recent_workload
```

只有证据明确为 academic 时才用：

```text
academic_load
```

# 八、P1：Structured Preferences 当前存在“双写双真相”

当前 `InteractionPreferenceService.apply_rule()` 对一个结构化 preference：

```text
verbosity
tone
suggestion_style
support preference
```

会同时：

```text
写 participant_interaction_rules
+
写 participant_interaction_styles / participant_support_preferences
```

这样：

```text
“以后回答短一点”
```

同时拥有两份状态：

```text
Style.verbosity = concise
Rule(category=verbosity, value=concise)
```

会带来：

```text
两个 source of truth
custom rule 上限被结构化字段占用
rule supersede 与 structured value 可能漂移
```

## 修改

内置 structured preference：

```text
verbosity
tone
suggestion_style
acknowledge_before_advice
ask_before_suggestion
max_suggestions
allow_supportive_follow_up
preferred_support_style
```

只写 canonical structured table。

`participant_interaction_rules` 只保留：

```text
不能映射到 built-in field、
但经过安全 normalize 的真正 custom rule
```

如果 v1 没有这种规则：

```text
可以暂时让 custom rule 为空
```

# 九、P1：第 4 条 Custom Rule 不应静默淘汰最旧规则

当前 max 3 条。

加入第 4 个不同 category 时，Repository 会自动 supersede oldest active rule。

用户对此无感知。

## 修改

同 category 更新：

```text
允许直接 supersede
```

第 4 个不同 rule：

```text
返回 preference_rule_limit_reached
```

并提示：

```text
“你已经有 3 条自定义规则，可以先删除或替换一条。”
```

不要静默丢弃。

# 十、P1：Memory Center 缺少明确“修改”能力

当前已有：

```text

删除
清空
```

但更新版方案写的是：

```text

修改
删除
清空
```

当前自然语言重新“记住”只能覆盖部分 conflict key，不等于统一编辑能力。

推荐：

```text
Memory Detail
[修改]
[删除]
```

修改用 fixed form：

```text
old content
→ new content
→ Backend validation
→ old superseded
→ new active
```

如果暂时不做，则文档必须收缩为：

```text
查看 / 删除 / 清空
```

并明确修改方式是：

```text
删除旧记忆 → 重新明确记住
```

用户体验上推荐补编辑。
