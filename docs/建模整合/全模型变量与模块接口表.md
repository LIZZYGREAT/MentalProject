# MindFlow 全模型变量与模块接口表

> 本文作为 MindFlow 压力建模体系的统一变量字典与模块接口规范。  
> 目的不是重复七份模型正文，而是让读者能够快速回答：
>
> - 某个变量是什么意思；
> - 它属于模型哪一层；
> - 它是事实、潜变量、上下文状态还是参数；
> - 它由谁产生、如何更新；
> - 是否允许从 EMA 学习；
> - 它最终流向哪个模块；
> - 哪些变量容易与它混淆。
>
> 本文采用最新交叉审计后的符号体系。

# 一、全模型层次总览

完整建模链路：

```text
[Layer 0] Real World / Raw Context
        ↓
[Layer 1] Structured Event / Obligation / Interaction Evidence
        ↓
[Layer 2] Event Potential / Pressure Sources / Lifecycle
        ↓
[Layer 3] Personal Appraisal
        ↓
[Layer 4] Effective D / Pressure Mechanisms / R
        ↓
[Layer 5] Temporalization & Channel Aggregation
        ↓
Q_D(t), Q_P(t), Q_R(t)
        ↓
[Layer 6] Slow Context States
C_D(t), C_U(t), F(t)
        ↓
[Layer 7] Latent Stress Dynamics
A(t), B(t), S(t)
        ↓
[Layer 8] Measurement / Inference
EMA, State Posterior, Parameter Posterior
        ↓
[Layer 9] Forecast / Risk / Validation
Predictive Distribution, Risk Probability, Synthetic Recovery
```

Bot Interaction 是一条并行分支：

```text
Conversation / Proactive Policy
        ↓
Bot Response Unit
        ↓
Support Representation
        ↓
Seen / Exposure
        ↓
Q_BS(t)
        ↓
A(t)
```

# 二、变量属性类型说明

本文使用以下属性标签。

| 属性 | 含义 |
|---|---|
| `Observed` | 可由系统直接观测、导入或用户明确报告 |
| `Inferred` | 由规则、LLM 或统计方法根据 observed evidence 推断 |
| `Latent` | 不可直接观测，需要模型推断 |
| `Context-derived` | 由上下文事实和行为记录确定或计算，不由 EMA residual 直接修正 |
| `Representation parameter` | 用于把事实映射成模型输入，原则上不与 Stress Dynamics 一起从 EMA 自由学习 |
| `Dynamic parameter` | 直接控制压力状态动力学，可通过 stress data 估计 |
| `Person-level candidate` | 只有满足 observability 条件时才允许个体化 |
| `Candidate mechanism` | 尚未无条件进入核心 v1，需要 ablation / recovery / held-out prediction 支持 |

# 三、模块 1：总体状态架构

## 1. $S_i(t)$

| 属性 | 内容 |
|---|---|
| 名称 | Latent Momentary Perceived Stress |
| 中文理解 | 个体 $i$ 在时刻 $t$ 的总体瞬时主观压力潜状态 |
| 所属层次 | Latent Stress Layer |
| 类型 | `Latent` |
| 定义 | $S_i(t)=A_i(t)+B_i(t)$ |
| 直接观测 | 否 |
| Primary EMA 是否测它 | 是，EMA 是对 $S$ 的 noisy measurement |
| 时间尺度 | 连续时间 |
| 是否允许 EMA 直接更新 | 是，通过 $A/B$ posterior assimilation 间接更新 |
| 上游 | $A_i(t),B_i(t)$ |
| 下游 | EMA Measurement、Forecast、Risk |
| 重要边界 | $S$ 不是 Context，也不是单个 Event Score |

直观理解：

> $S(t)$ 是我们真正想预测的“此刻整体压力”，但系统平时看不到它，只能偶尔通过 EMA 得到有噪声观测。

---

## 2. $A_i(t)$

| 属性 | 内容 |
|---|---|
| 名称 | Signed Acute Stress Component |
| 中文理解 | 相对于 Background 的快速、短时压力偏移量 |
| 所属层次 | Latent Stress Layer |
| 类型 | `Latent` |
| 是否允许为负 | 是 |
| 主要时间尺度 | 分钟—小时 |
| 直接观测 | 否 |
| EMA 是否直接测它 | 否 |
| 主要输入 | $Q_D,Q_P,Q_R$；BI1 中增加 $Q_{BS}$ |
| 动力学参数 | $\kappa_\uparrow,\kappa_{\downarrow,i}$ |
| 下游 | $S=A+B$ |

解释：

- $A>0$：当前事件、deadline、任务执行等把压力推高到 Background 之上；
- $A\approx0$：当前主要由 Background 决定；
- $A<0$：Recovery / Support 等让此刻压力暂时低于 Background。

因此 $A$ 不应理解为“非负的急性压力分数”，而是：

$$
\boxed{
Signed\ Acute\ Contribution
}
$$

---

## 3. $B_i(t)$

| 属性 | 内容 |
|---|---|
| 名称 | Background Stress State |
| 中文理解 | 个体跨日持续携带的慢变化背景压力 |
| 所属层次 | Latent Stress Layer |
| 类型 | `Latent` |
| 主要时间尺度 | 天—周 |
| 直接观测 | 否 |
| EMA 是否直接测它 | 否 |
| 主要输入 | $C_D,C_U,F$ |
| 个体参数 | $S_i^0,g_i^B$ |
| 动态参数 | $\kappa_B$ |
| 下游 | $S=A+B$ |

直观理解：

> $B$ 不是“今天某件事让我紧张”，而是最近积累的 workload、unfinished obligations、sleep debt 等共同形成的背景压力水平。

# 四、模块 2：事件与原始上下文变量

## 1. Event Identifier：$e$

| 属性 | 内容 |
|---|---|
| 名称 | Event ID |
| 中文理解 | 一个具体课程、任务、会议、恢复活动等事件对象 |
| 所属层次 | Structured Event Layer |
| 类型 | `Observed / Structured` |
| 来源 | calendar、course table、task system、conversation evidence |
| 是否进入压力方程 | 不直接进入 |
| 主要作用 | 作为 Event Potential、Lifecycle、Appraisal 的索引 |

---

## 2. $t_e^{start},t_e^{end}$

| 属性 | 内容 |
|---|---|
| 名称 | Event Start / End Time |
| 中文理解 | 事件计划或实际的起止时间 |
| 类型 | `Observed` 或 `Inferred` |
| 所属层次 | Event / Exposure |
| 是否 dynamic parameter | 否 |
| 下游 | Temporal Kernel、Lifecycle、Exposure |
| 关键规则 | actual interval 优先于 scheduled interval |

必须避免：

> 已经知道 actual duration 只有一半，却又额外用 $Z^{exec}=0.5$ 再把暴露缩小一次。

这由 `SingleExposureEncodingRule` 约束。

---

## 3. $W_e^{rem}(t)$

| 属性 | 内容 |
|---|---|
| 名称 | Remaining Effective Effort |
| 中文理解 | 当前任务距离完成还需要多少“有效工作量” |
| 所属层次 | Task / Obligation Layer |
| 类型 | `Observed / Inferred` |
| 时间依赖 | 是 |
| 来源优先级 | 用户当前估计 > observed progress > structured progress > historical prior > task-class prior |
| 是否 latent stress parameter | 否 |
| 是否由 EMA 更新 | 否 |
| 下游 1 | $U_{ddl}(t)$ |
| 下游 2 | $C_U(t)$ |
| 易混淆 | Progress |

必须保持：

$$
\boxed{
Progress
\rightarrow
W^{rem}
}
$$

而不是：

$$
C_U=f(Progress,W^{rem})
$$

---

## 4. $W_e^{total}$

| 属性 | 内容 |
|---|---|
| 名称 | Estimated Total Effective Effort |
| 中文理解 | 完成该任务预计总共需要多少有效工作量 |
| 类型 | `Observed / Inferred` |
| 所属层次 | Task Representation |
| 下游 | 可用于根据 progress 推算 $W^{rem}$ |
| 是否直接进入 stress | 否 |

如果：

$$
Progress=p
$$

且：

$$
W^{total}
$$

可信，则可近似：

$$
W^{rem}=(1-p)W^{total}
$$

---

## 5. $T_e^{capacity}(t)$

| 属性 | 内容 |
|---|---|
| 名称 | Deadline-Specific Effective Available Capacity |
| 中文理解 | 从当前时刻到该 deadline 之间，真正可用于完成此任务的有效工作容量 |
| 所属层次 | Event Pressure Source |
| 类型 | `Context-derived` |
| 时间依赖 | 是 |
| 是否等于 calendar free time | 否 |
| 下游 | $U_{ddl}(t)$ |
| 易混淆 | $C_i^{ref}$ |

它回答：

> “在 deadline 前，我到底还有多少实际可用于做这件事的容量？”

而不是：

> “这个人通常一周能工作多少小时？”

后者是：

$$
C_i^{ref}
$$

---

# 五、模块 3：Event Potential 与 Pressure Sources

## 1. $D_e^{pot}$

| 属性 | 内容 |
|---|---|
| 名称 | Demand Potential |
| 中文理解 | 事件本身在单位暴露期间的 Demand 强度潜力 |
| 所属层次 | Event Potential |
| 类型 | `Representation-derived` |
| 典型范围 | $[0,1]$ |
| 是否包含个人能力 | 否 |
| 是否包含 duration | 原则上不直接重复编码总 duration |
| 是否从 EMA 自由学习 | 否 |
| 下游 | Personal Appraisal $\rightarrow D^{eff}$ |
| 易混淆 | $C^{exec}$ |

它回答：

> “这件事本身做起来有多费认知/执行/体力？”

而不是：

> “这个人觉得自己能不能做好？”

---

## 2. $\mathbf P_e^{src}(t)$

统一定义：

$$
\boxed{
\mathbf P_e^{src}(t)
=
[
U_{ddl,e}(t),
U_{context,e}(t),
D_{s,e}
]
}
$$

这是 Pressure Sources Vector。

它不是最终 Pressure。

---

## 3. $U_{ddl,e}(t)$

| 属性 | 内容 |
|---|---|
| 名称 | Deadline / Time-Scarcity Source |
| 中文理解 | 当前剩余工作量相对于 deadline 前有效容量有多紧张 |
| 所属层次 | Pressure Source |
| 类型 | `Context-derived` |
| 范围 | $[0,1]$ |
| 时间依赖 | 强 |
| 主要输入 | $W^{rem}(t),T^{capacity}(t)$ |
| 概念式 | $f(W^{rem}/T^{capacity})$ |
| 是否含 personal importance | 否 |
| 是否需要再乘 proximity kernel | 否 |
| 下游 | Pressure Appraisal |

它本身就会随着：

- deadline 临近；
- progress；
- capacity 变化；

动态改变。

因此不能再额外加一个“越临近越强”的 deadline anticipation kernel，否则重复编码 proximity。

---

## 4. $U_{context,e}(t)$

| 属性 | 内容 |
|---|---|
| 名称 | Structural Uncertainty |
| 中文理解 | 事件本身客观存在的不确定性 |
| 所属层次 | Pressure Source |
| 类型 | `Context-derived` |
| 范围 | $[0,1]$ |
| 时间依赖 | 可以变化 |
| 来源 | requirement、dependency、rules、result mechanism 等 |
| 下游 | $p_{unc}^{app}(t)$ |
| 易混淆 | $U^{perc}$ |

例如：

- 作业要求没讲清楚；
- 是否抽查未知；
- 外部 dependency 未解决。

必须保持：

$$
\boxed{
U_{context}
\neq
U^{perc}
}
$$

---

## 5. $D_{s,e}$

| 属性 | 内容 |
|---|---|
| 名称 | Social-Evaluative Structure |
| 中文理解 | 事件是否包含公开展示、他人评价、答辩、面试等结构 |
| 所属层次 | Pressure Source |
| 类型 | `Representation-derived` |
| 范围 | $[0,1]$ |
| 时间依赖 | 结构本身较稳定 |
| 下游 | social-evaluative temporal activation |
| 易混淆 | Personal Importance |

它回答：

> “这件事有没有被评价/展示的结构？”

不回答：

> “我在不在乎别人怎么看？”

---

## 6. $R_e^{pot}$

| 属性 | 内容 |
|---|---|
| 名称 | Recovery Potential |
| 中文理解 | 活动本身提供多少恢复机会 |
| 所属层次 | Event Potential |
| 类型 | `Representation-derived` |
| 范围 | $[0,1]$ |
| 主要语义来源 | detachment、relaxation、control、relatedness、mastery |
| 是否等于 actual recovery | 否 |
| 下游 | $R^{eff}$ |
| 是否从 EMA 自由学习 | 否 |

它回答：

> “这个活动本身有没有恢复价值？”

但不回答：

> “这个活动对这个具体人是不是有效？”

后者由：

$$
F^{rec}
$$

处理。

# 六、模块 4：Lifecycle 与 Exposure

## 1. $Z_e^{exec}(t)$

| 属性 | 内容 |
|---|---|
| 名称 | Execution / Engagement Intensity |
| 中文理解 | 事件当前实际执行或参与的强度 |
| 所属层次 | Lifecycle / Exposure |
| 类型 | `Observed / Inferred` |
| 范围 | $[0,1]$ |
| 下游 | Demand |
| 关键规则 | 不再把“已参加时长比例”和“参与强度”重复编码 |

如果 actual interval 已知：

- duration 由 interval 表示；
- 正常参与期间可令 $Z^{exec}=1$。

只有不知道精确 interval、只知道“大概参与一半”时，才可用 fractional $Z^{exec}$ 近似。

| 所属层次 | Lifecycle |
| 类型 | `Context-derived` |
| 范围 | $[0,1]$ |
| 下游 | $p_{ddl}^{app}(t)$ |

例如 task completed 后：

$$
Z^{ddl}\rightarrow0
$$

---

## 3. $Z_e^{unc}(t)$

| 所属层次 | Lifecycle |
| 类型 | `Context-derived` |
| 范围 | $[0,1]$ |
| 下游 | $p_{unc}^{app}(t)$ |

---

## 4. $Z_e^{soc}(t)$

| 属性 | 内容 |
|---|---|
| 名称 | Social-Evaluative Exposure Gate |
| 中文理解 | 当前是否真正进入 social evaluation 的作用阶段 |
| 所属层次 | Lifecycle / Temporal Exposure |
| 类型 | `Context-derived` |
| 范围 | $[0,1]$ |
| 下游 | social-evaluative pressure |

---

## 5. $Z_e^{occ}(t)$

| 属性 | 内容 |
|---|---|
| 名称 | Recovery Activity Occurrence |

| 类型 | `Observed / Inferred` |
| 范围 | $[0,1]$ |
| 下游 | Recovery |

# 七、模块 5：Personal Appraisal

Appraisal 变量统一属于：

$$
\boxed{
Participant\text{-}Event\ Appraisal
}
$$

不等于 Event Fact，也不等于 EMA。

---

## 1. $C_{i,e}^{exec}$

| 属性 | 内容 |
|---|---|
| 名称 | Execution Competence |
| 中文理解 | 用户认为自己处理这件事有多有能力、是否匹配 |
| 层次 | Personal Appraisal |
| 类型 | `Belief / Inferred` |
| 状态 | Low / Medium / High / Unknown belief |
| 下游 | Demand |
| 不应来源于 | EMA、objective difficulty |
| 稳定性 | 可有较强 stable prior |

它回答：

> “这件事对我来说做起来有多吃力？”

而不是：

> “这件事客观有多难？”

---

## 2. $I_{i,e}$

| 属性 | 内容 |
|---|---|
| 名称 | Personal Importance / Stakes |
| 中文理解 | 事件或结果对该用户有多重要 |
| 层次 | Personal Appraisal |
| 类型 | `Belief / Inferred` |
| 状态 | Low / Medium / High |
| 下游 | Pressure |
| 作用次数 | 一次 |
| 不应由 | credit / course type 直接确定 |

它在 within-event Pressure structure 聚合后只作用一次。

---

## 3. $C_{i,e}^{out}$

| 属性 | 内容 |
|---|---|
| 名称 | Outcome Control |
| 中文理解 | 用户认为自己还能多大程度影响最终结果 |
| 层次 | Personal Appraisal |
| 类型 | `Belief / Inferred` |
| 下游 | Deadline Pressure、Uncertainty Pressure |
| 稳定性 | episode-specific，stable prior 较弱 |

---

## 4. $U_{i,e}^{perc}$

| 属性 | 内容 |
|---|---|
| 名称 | Perceived Uncertainty |
| 中文理解 | 用户主观感觉这件事有多不确定 |
| 层次 | Personal Appraisal |
| 类型 | `Belief / Inferred` |
| 下游 | Uncertainty Pressure |
| 易混淆 | $U_{context}$ |
| 稳定性 | episode-specific |

必须保持：

$$
\boxed{
StructuralUncertainty
\neq
PerceivedUncertainty
}
$$

---

## 5. $F_{i,e}^{rec}$

| 属性 | 内容 |
|---|---|
| 名称 | Personal Recovery Fit |
| 中文理解 | 某种恢复活动对这个人实际是否“适合、有效” |
| 层次 | Personal Appraisal |
| 类型 | `Belief / Inferred` |
| 下游 | Recovery |
| 稳定性 | 可形成 activity-specific stable prior |
| 易混淆 | $F(t)$ |

必须注意：

$$
F_{i,e}^{rec}
$$

是“个人-活动适配度”，而：

$$
F_i(t)
$$

是“Sleep-Dominant Recovery Debt”。

二者完全不是同一个变量。

---

## 6. $\boldsymbol{\pi}_{i,e}^{(k)}$

| 属性 | 内容 |
|---|---|
| 名称 | Appraisal Belief Distribution |
| 中文理解 | 某 appraisal 当前 Low / Medium / High 的概率分布 |
| 层次 | Appraisal Inference |
| 类型 | `Belief state` |
| 形式 | $[P(Low),P(Medium),P(High)]$ |
| 下游 | exact marginalization / scenario sampling |

必须保持：

$$
\boxed{
Unknown
\neq
Medium
}
$$

---

## 7. $\ell(a)$

定义：

$$
\boxed{
\ell(a)
=
\begin{cases}
-1,&Low\\
0,&Medium\\
+1,&High
\end{cases}
}
$$

属性：

| 属性 | 内容 |
|---|---|
| 类型 | `Representation mapping` |
| 是否 learnable | 否 |
| 用途 | 把 ordinal appraisal 转成调制方向 |
| 含义 | 只表达顺序，不声称心理距离精确等距 |

---

## 8. $\rho_{app}$

| 属性 | 内容 |
|---|---|
| 名称 | Appraisal Modulation Strength |
| 中文理解 | Low/Medium/High appraisal 对输入放大或削弱的统一强度 |
| 层次 | Representation |
| 类型 | `Representation parameter` |
| 条件 | $\rho_{app}>1$ |
| 是否 person-specific | 否 |
| 是否从 EMA 自由学习 | 否 |
| 状态 | Structure defined；numeric value pending freeze |

---

## 9. $\mathcal T_\epsilon(x,m)$

定义：

$$
\boxed{
\mathcal T_{\epsilon}(x,m)
=
\begin{cases}
0,&x=0\\[2mm]
\sigma
\left[
\operatorname{logit}
\left(
\operatorname{clip}(x,\epsilon,1-\epsilon)
\right)
+\log m
\right],
&x>0
\end{cases}
}
$$

| 属性 | 内容 |
|---|---|
| 名称 | Boundary-Safe Appraisal Transform |
| 中文理解 | 将 Event Source 与 Personal Appraisal 结合，同时保持有界 |
| 类型 | `Representation operator` |
| 输出范围 | $[0,1]$ |
| 是否 learnable | 否 |
| 主要优点 | $x=0$ 时不会凭空创造机制；$x=1$ 时仍允许 appraisal 下调 |

---

# 八、模块 6：Effective Demand / Pressure / Recovery

## 1. $D_{i,e}^{eff}$

定义：

$$
\boxed{
D_{i,e}^{eff}
=
\mathcal T_\epsilon
\left(
Z_e^{exec}D_e^{pot},
\rho_{app}^{-\ell(C_{i,e}^{exec})}
\right)
}
$$

| 属性 | 内容 |
|---|---|
| 名称 | Effective Demand |
| 中文理解 | 事件真实执行后，对这个具体用户形成的有效 Demand |
| 层次 | Effective Input |
| 范围 | $[0,1]$ |
| 上游 | $D^{pot},Z^{exec},C^{exec}$ |
| 下游 | Demand temporalization |

---

## 2. $p_{ddl,i,e}^{app}(t)$

定义：

$$
\boxed{
p_{ddl,i,e}^{app}(t)
=
\mathcal T_\epsilon
\left(
Z_e^{ddl}(t)U_{ddl,e}(t),
\rho_{app}^{-\ell(C_{i,e}^{out})}
\right)
}
$$

| 属性 | 内容 |
|---|---|
| 名称 | Appraised Deadline Pressure Source |
| 中文理解 | deadline scarcity 经 outcome-control appraisal 修正后的 pressure source |
| 层次 | Pressure Mechanism |

# 二十三、当前模型接口的核心规则

1. Context 不直接等于 Stress。
2. Event Potential 不等于 Realized Exposure。
3. Exposure 不等于 Appraisal。
4. Appraisal 不等于 EMA。
5. Pressure Sources 不应先过早压成 static scalar。
6. Deadline scarcity 本身是 time-varying source，不再叠加 proximity kernel。
7. Personal Importance 在 event Pressure 中只作用一次。
8. Partial exposure 只允许一个主要编码路径，避免 duration 与 fractional gate 双重计算。
9. $C_D/C_U/F$ 均为 context-derived，不由 EMA residual 直接改写。
10. $A$ 是 signed acute component，可为负。
11. $B$ 是 slow background latent state。
12. $S=A+B$ 是 Primary EMA 对应的 latent target。
13. $\tau_D,\tau_B,\tau_{BS}$ 分别属于不同机制，不能混用。
14. Representation layer 与 Stress Dynamics fitting 必须分离。
15. Person-level parameter 只有在观测条件充分时才晋级。
16. Bot Support 仍是 BI1 candidate，不属于无条件 core model。
17. Forecast 必须传播 state / parameter / input uncertainty。
18. Formal evaluation 必须使用 pre-assimilation prediction。
19. 所有 prospective forecast 必须遵守 `known_at`。
20. 同一变量在模型中应保持一个名字、一个语义、一个 owner module。
